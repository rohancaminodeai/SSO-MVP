## The feature

A **single source of truth for the trust model**. Every token constant and env value the system
depends on is defined and validated in one place, so no other file may hardcode them and a
mis-configured service crashes at boot instead of minting/accepting bad tokens later.

## Why it matters

- **Pinning is a security control, not a style choice.** `ALG="RS256"` lives here so verification
  can pin `algorithms:["RS256"]` and reject `alg:none` / HS256 key-confusion attacks.
- **Fail-fast config** turns a silent production mistake (wrong issuer, typo'd tenant) into a loud
  startup error.
- **Factory-friendly:** `loadConfig(env, opts)` takes its env as an argument, so tests inject a
  throwaway config — the pattern every later service (`createApp(deps)`) builds on.

## Top 3 must-know concepts

1. **Asymmetric signing + `alg` pinning.** IdP signs with a *private* RS256 key; tenants verify with
   the *public* key only and **pin the algorithm**. Never accept `none` or a symmetric alg — that's
   how `alg:none` and RS↔HS key-confusion attacks get in. (ADR-0001, ADR-0002.)
2. **Centralize authentication, keep authorization local** — and the **401 vs 403** taxonomy.
   401 = "I don't know who you are" (bad/missing token). 403 = "I know you, but you can't be here"
   (entitlement check). One IdP sees passwords; each tenant decides access locally.
3. **Offline verification via JWKS + the 6 ordered checks.** Tenants cache the IdP's public keys and
   verify with **no call back to the IdP**, running the 6 checks in order — crucially **check #5
   (entitlement) runs before any DB read** (the isolation invariant). (ADR-0004.)

## Technical decisions (ADRs)

| ADR | Decision | Why |
|---|---|---|
| 0001 | RS256 asymmetric signing | Private key signs at the IdP; tenants verify with the public key. |
| 0002 | Pin the algorithm to RS256 | Defeats `alg:none` / HS256 key-confusion forgery. |
| 0003 | Entitlements inside the token | Tenants learn permissions from the token, no extra IdP lookup. |
| 0004 | Offline verification (JWKS) | Tenants cache public keys and verify locally — fast and resilient. |
